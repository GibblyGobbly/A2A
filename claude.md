# Claude Code Instructions for A2A

A2A (OmniConvert) is a local, offline Android file converter and media compressor built with Flutter (Dart ^3.12.2) and native Android Kotlin (API 24+).

## Essential Commands

### Development and Analysis
- Install dependencies: `flutter pub get`
- Run static analysis: `flutter analyze`
- Check code formatting: `dart format --output=none --set-exit-if-changed .`
- Format codebase: `dart format .`

### Testing
- Run all unit and widget tests: `flutter test`
- Run a single test file: `flutter test test/services/format_detector_test.dart`

### Building and Running
- Run in debug mode: `flutter run`
- Build release APK: `flutter build apk --release`
- Build release App Bundle: `flutter build appbundle --release`

## Anti-Vibe-Coding Rules (Strict UI and Code Quality Guardrails)

Claude frequently falls into "vibe-coding" patterns—generating generic, superficial, ungrounded code and AI-slop UI aesthetics. In this codebase, the following anti-vibe-coding rules are strictly enforced:

### 1. Banned Visual Anti-Patterns (No AI-Slop UI)
- Never use dark-mode neon gradients (electric violet, purple, cyan glows).
- Never use glassmorphism, blurred backdrop filters, or soft fuzzy drop shadows on cards.
- Never use web-centric desktop layouts (such as centered marketing hero banners or three-column feature landing blocks) inside this mobile app.
- Never use arbitrary, ungrounded inline colors (e.g. `Colors.purpleAccent`, `Color(0xFF6366F1)`). Use solely the design tokens defined in `lib/theme/app_theme.dart`.
- Never invent decorative, non-functional chips or fake interactive badges that do not perform real work.
- Never use low-contrast text (e.g. light gray on white or muted gray on dark). All text must meet WCAG AAA contrast ratios.

### 2. Required Mobile-Native Ergonomics
- Adhere strictly to clean, tactile Material 3 utility design: flat surfaces, crisp 1px borders (`Color(0xFFE2E8F0)`), zero card elevation, and purposeful typography.
- Ensure all interactive touch targets meet or exceed Android minimum standards (at least 48x48 dp).
- Align headings and section labels to the left; avoid centered marketing-style typography.
- Use a disciplined 4dp/8dp spatial grid for padding and margins. Do not use random, uneven padding numbers (e.g. 13dp, 19dp, 27dp).
- Always accommodate Android edge-to-edge system bars, keyboard insets, and notch safe areas.

### 3. Engineering Rigor (No Hallucinated Completeness)
- Never write placeholder functions or mock implementations (such as `// TODO: Implement later` or empty stubs) in user-facing paths.
- If a format or option is exposed in the UI, its conversion pipeline must be fully implemented, tested, and operational on-device.
- Never swallow exceptions with empty catch blocks or raw `print(e)` statements. Always handle errors robustly and return structured `ConversionResult` objects.
- Never introduce new third-party dependencies on a whim without explicit user instruction. Keep the dependency footprint lean.

## Critical Architectural Constraints

1. Strictly Offline and On-Device:
   - Never import, propose, or invoke cloud APIs, remote servers, web scrapers, or third-party telemetry.
   - All conversions must execute on-device via FFmpeg, pure Dart packages, or native Android platform channels.

2. Zero Emojis Rule:
   - Do not include emojis anywhere in source code, comments, documentation, commit messages, or terminal outputs.

3. Architectural Layering:
   - UI views belong in `lib/views/` and reusable widgets in `lib/widgets/`.
   - All conversion and transcoding logic belongs strictly in `lib/services/`.
   - Data models belong in `lib/models/`.
   - Styling and color constants belong in `lib/theme/app_theme.dart`.

4. Error Handling Contract:
   - Conversion methods must never throw unhandled exceptions to UI callers.
   - Always catch exceptions and return a `ConversionResult` with `isSuccess: false` and a descriptive `errorMessage`.
   - Always delete partial or corrupted output files on conversion failure.

5. Storage and File System Standards:
   - Output files must be saved under the directory returned by `AppStorageService.getOutputDirectory()` (defaults to `/storage/emulated/0/Download/OmniConvert`).
   - Every newly created media file (image, video, audio) must trigger `AppStorageService.notifyMediaScanner(targetPath)` so it appears in Android system gallery apps.
   - Always guard native platform channel calls (`com.universal.converter/storage`) with `if (Platform.isAndroid)`.

6. Media and Video Processing Rules:
   - FFmpeg execution must include `-threads 8` for multi-core performance.
   - Always clear statistics callbacks (`FFmpegKitConfig.enableStatisticsCallback(null)`) after video conversion finishes or errors.
   - If AV1 (`libaom-av1`) fails or is unsupported by hardware, execute the fallback pipeline to `libx264`.
   - Video commands producing MP4 must include `-movflags +faststart`.
   - Audio extraction commands must include `-vn` to strip unused video streams.

7. Memory and Concurrency:
   - Never block Flutter's main UI isolate with synchronous file processing.
   - In batch conversions, iterate sequentially to allow immediate garbage collection of intermediate image and document buffers.
   - Always dispose controllers (`PageController`, `TextEditingController`) and document instances (`sf.PdfDocument.dispose()`).
